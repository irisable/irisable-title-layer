## Request-boundary audit

- Migration admin-post handlers call `AdminPage::authorize`: POST, manage_options,
  scalar nonce, then action-specific `check_admin_referer` before scan/import/export/rollback.
- Migration AJAX calls `AjaxController::authorize` before processing a batch:
  POST, manage_options, scalar nonce and `check_ajax_referer`.
- Sequence initialize/continue/rollback/move/undo and structure enable call
  `verify_action` before changing ordering. AJAX move/search call `verify_ajax`.
  Both now check POST and string nonce input before the core nonce verifier.
- Classic editor writes require edit_post, a string action nonce, a recognized
  post type, and exclude revisions/autosaves. Series term forms require edit_term
  and a string action nonce. Each recognized field uses its own sanitizer.
- REST uses WordPress authentication (including cookie nonce verification) and
  permission callbacks / edit_post or edit_term metadata authorization. Application
  Password clients do not require a browser nonce. No custom bypass was added.
- Settings use register_setting, sanitization, settings_fields and core options.php.
- Read-only health filters/pagination sanitize query arguments and gate admin
  access; adding a nonce to public archive/navigation URLs is not appropriate.
